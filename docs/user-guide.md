# RAG Studio 知识库使用说明

本文面向知识库的日常使用者和管理员，介绍登录、资料入库、检索问答、知识库管理及常用配置。
部署、备份和升级操作另见[部署与发布](deployment.md)。

## 1. 访问与登录

使用管理员提供的 HTTPS 地址访问系统。本机使用时，默认地址为：

- Docker 生产入口：<http://127.0.0.1:8080>
- 本地开发入口：<http://127.0.0.1:8501>

生产入口会弹出登录框：

- 默认用户名：`admin`
- 密码：由管理员设置，请勿将密码写入文档、聊天记录或公开仓库

公网 Quick Tunnel 地址是临时地址，电脑、隧道或网络重启后可能变化。地址失效时，请向管理员获取
新的 HTTPS 地址。

登录后，左侧栏会显示后端状态、当前生成模型和 Embedding 模型。若显示“后端未连接”，先点击
“刷新状态”；仍未恢复时联系管理员检查服务。

## 2. 第一次使用

建议按以下顺序完成首次使用：

1. 打开“配置中心”，确认当前 LLM、Embedding 和 Ollama 状态正常。
2. 打开“知识库”，上传一份内容清晰、可复制文字的文档。
3. 等待“上传并入库”完成，确认页面显示新文档和生成的知识片段数。
4. 打开“对话工作台”，先选择“严格知识库”和“相似度”。
5. 输入一个能从文档中直接找到答案的问题。
6. 展开回答下方的“引用来源”，核对文件名、页码或代码行号。

生产部署默认使用 Ollama 本地模型和本地中文 Embedding。若页面显示 `demo`，系统只用于验证上传、
检索和界面流程，不代表真实大模型的回答质量。

## 3. 准备知识资料

### 3.1 支持的文件

系统支持以下资料直接上传：

- 文档：PDF、DOCX、TXT、Markdown
- 代码与配置：Python、JavaScript、TypeScript、Java、Go、Rust、C/C++、C#、PHP、Ruby、Swift、
  Kotlin、SQL、YAML、JSON、TOML 等
- 代码库：ZIP 压缩包

建议：

- PDF 应包含可选择、可复制的文字。纯扫描图片 PDF 当前没有 OCR，可能生成 0 个片段。
- TXT、Markdown、代码和配置文件尽量使用 UTF-8 编码。
- 一个文件只保留一个明确版本，避免新旧制度、合同或产品说明互相冲突。
- 标题、章节名、函数名和文件名应清晰，它们会帮助系统检索。
- 超长资料可按主题拆分，文件名中写明部门、主题、地区或日期。

### 3.2 准备代码库 ZIP

系统不直接拉取 GitHub 地址。请先将代码仓库下载或压缩为 `.zip`，再从“知识库”页面上传。

ZIP 可以包含一个公共根目录。系统会保留相对路径，并自动忽略 `.git`、`node_modules`、`.venv`、
`dist`、`build`、缓存目录、二进制文件及不支持的文件类型。

默认限制为：

| 项目 | 默认限制 |
| --- | ---: |
| ZIP 文件大小 | 25 MB |
| 可入库文件数 | 2,000 |
| 单个文件大小 | 2 MB |
| 解压后可入库文件总大小 | 50 MB |

压缩包中不要放密码、私钥、`.env`、访问令牌或客户隐私数据。

## 4. 上传并建立知识库

1. 从左侧栏进入“知识库”。
2. 点击文件选择区域，选择一个文档或 ZIP。
3. 点击“上传并入库”。
4. 等待解析、切分、Embedding 和向量写入完成。
5. 查看成功提示中的文件数和片段数。

大文档、代码库或首次加载本地 Embedding 模型时可能需要几分钟。处理中不要重复点击上传，也不要
关闭运行服务的电脑。

入库完成后：

- “文档”页签显示文件名、片段数和使用的 Embedding 模型。
- “代码库”页签显示代码库名称、入库文件数、片段数和忽略文件数。
- 页面顶部显示知识片段、文档/代码库、生成模型和 Embedding 统计。

## 5. 使用对话工作台

### 5.1 回答模式

| 模式 | 行为 | 推荐场景 |
| --- | --- | --- |
| 严格知识库 | 只依据检索到的资料回答；资料不足时明确拒答 | 制度、合同、手册、审计和需要可追溯依据的问答 |
| 知识库增强 | 优先使用知识库；资料不足时允许模型用通用知识补充并标明来源 | 解释、写作、方案建议和开放性问题 |

重要事实默认使用“严格知识库”。“知识库增强”中的模型补充不等于组织内部事实，应人工核验。

### 5.2 检索策略

| 策略 | 特点 | 推荐场景 |
| --- | --- | --- |
| 相似度 | 优先返回与问题最相关的片段 | 明确事实、单一主题、文件定位 |
| MMR 多样性 | 在相关性之外减少重复片段 | 总结多个章节、比较不同方案、结果过于重复时 |

“返回片段”控制最终提供给模型的来源数量，范围为 1 到 10。通常保留默认值 `4`；答案缺少上下文时
可尝试 6 到 8，简单事实问题不必设置过大。

### 5.3 提问方法

提问应包含明确对象、时间、文件或代码符号。例如：

- “员工报销制度中，差旅住宿的标准是多少？”
- “根据 2026 年产品手册，离线模式有哪些限制？”
- “`app/rag/service.py` 中 `answer_question` 的处理流程是什么？”
- “比较 A 方案和 B 方案的实施条件，并分别列出引用来源。”

避免只问“这个是什么”“总结一下”等缺少对象的问题。需要总结时，写明文件名、章节或主题范围。

### 5.4 核对回答和来源

每次回答下方会显示：

- 答案依据：知识库、模型通用知识或二者混合
- 总耗时、候选数、返回片段数和检索策略
- 当前生成模型
- 引用来源

展开“引用来源”可查看文件名、页码、代码行号、综合分、向量分、关键词命中和原始片段。点击
“下载来源”可将单个片段保存为文本。

不要只依据分数判断答案是否正确。涉及财务、法律、医疗、合同或生产操作时，应打开原始文件核对
上下文和版本。

### 5.5 对话记录

- “导出对话”会生成 Markdown 文件，包含问题、回答及来源列表。
- “清空”只清除当前浏览器会话中的对话记录，不会删除知识库资料。
- 刷新页面或关闭浏览器后，不应把当前对话当作永久保存记录；重要结果请及时导出。

## 6. 管理知识库

### 6.1 删除文档

“文档”页签中的“删除”会删除该文档及其向量片段。该操作立即执行，删除前请确认文件名。

### 6.2 管理代码库

- “重建”：使用服务器中已保存的代码库文件重新生成索引，适合修改切分参数后重建。
- “删除”：删除代码库记录、解压后的源文件和全部对应向量。

若代码内容已经更新，请删除旧代码库并上传新的 ZIP；“重建”不会自动从 GitHub 获取新代码。

### 6.3 清空知识库

“清空知识库”会删除全部文档、代码库和向量索引，页面会要求二次确认。该操作与“清空对话”不同，
不可通过界面撤销。执行前应确认管理员已经备份重要数据。

## 7. 配置中心

普通使用者通常无需修改配置。参数调整应由了解 RAG 检索和模型成本的管理员执行。

### 7.1 模型服务

生成模型支持：

- `demo`：不调用真实大模型，仅用于流程测试。
- `ollama`：使用本地 Ollama 模型，资料和生成过程可保留在本机环境。
- `openai`：使用 OpenAI 或兼容服务，需要 API Key，可能产生费用并将必要请求发送给服务商。

Embedding 支持 `demo`、`local` 和 `openai`。生产环境建议继续使用已经建立索引时的 Embedding
Provider 与模型。

OpenAI API Key 保存后不会在界面回显。留空表示保持原 Key；勾选“清除现有 Key”后保存，才会删除。

不要随意修改生产环境中的 Ollama Base URL。Docker 部署通常使用 `http://ollama:11434`，本地开发
才通常使用 `http://127.0.0.1:11434`。

### 7.2 检索与索引

常用参数含义：

| 参数 | 作用 |
| --- | --- |
| 默认 Top K | 每次问答默认返回多少个片段 |
| 候选数量 | 初始检索阶段取回多少候选片段 |
| MMR 相关性权重 | 越接近 1 越强调相关性，越接近 0 越强调多样性 |
| 向量/关键词/文件名/符号权重 | 控制混合排序，各项总和必须等于 1 |
| Chunk Size | 每个知识片段的大致长度 |
| Chunk Overlap | 相邻片段重复保留的上下文长度 |
| Reranker | 对候选片段执行二次语义排序 |

启用 `cross_encoder` Reranker 后，首次使用需要下载额外模型，CPU 环境中的问答速度也会下降。

修改以下配置后必须清空知识库并重新上传资料：

- Embedding Provider
- Embedding 模型
- Chunk Size
- Chunk Overlap

否则旧索引和新配置不一致，检索可能失败或结果不可靠。页面出现“需要清空知识库并重新入库”警告时，
不要继续依赖现有问答结果。

## 8. 提高回答质量

建议按以下顺序排查和优化：

1. 确认正确版本的资料已经入库，并且片段数不为 0。
2. 使用“严格知识库”测试能否准确召回原文。
3. 在问题中加入文件名、章节、产品名、函数名或关键术语。
4. 展开来源，判断是“未检索到正确片段”还是“模型没有正确总结片段”。
5. 结果重复时切换 MMR；上下文不足时适当提高返回片段数。
6. 只有在有明确评估集时再调整混合权重、Chunk 或 Reranker。

不要同时大幅修改多个参数。每次只修改一组设置，并使用同一组问题比较前后结果。

## 9. 常见问题

### 登录后反复弹出密码框

确认用户名为 `admin`，并重新输入管理员提供的新密码。浏览器可能缓存旧的 Basic Auth 凭据，修改密码
后可关闭全部相关页面，或使用无痕窗口重新登录。

### 公网地址打不开

临时 Cloudflare Tunnel 地址可能已变化，或运行服务的电脑已经关机。向管理员获取最新地址，并确认
电脑、Docker Desktop 和隧道均在运行。

### 页面显示“后端未连接”

点击左侧“刷新状态”。若仍未恢复，管理员应检查 Docker 服务状态和日志。

### 上传后没有生成片段

检查文件是否为空、是否为扫描图片 PDF、文本是否使用可读取编码，以及 ZIP 中是否只有被忽略的目录
或二进制文件。

### Ollama 模型未安装

在“配置中心”选择状态区列出的已安装模型。管理员也可以先下载所需模型，再返回页面刷新状态。

### 第一次问答很慢

首次运行可能正在加载生成模型、Embedding 或 Reranker。CPU 推理通常比 GPU 慢；短时间内重复问答一般
会更快。

### 提示 Embedding 与索引不一致

这不是普通提示。先备份需要保留的数据，再清空知识库，并在当前配置下重新上传全部资料。

## 10. 数据与安全注意事项

- 当前登录方式是共享账号，不是多用户权限系统，不同使用者之间没有独立知识库隔离。
- 不要上传超出授权范围的个人信息、客户资料、密码、私钥、访问令牌和商业机密。
- 使用 OpenAI 或兼容服务前，应确认组织的数据合规要求和服务商的数据处理政策。
- 公网只能使用 HTTPS 地址，不要通过明文 HTTP 暴露登录入口。
- 大模型回答可能出错；关键结论必须核对引用来源和原始文件。
- 定期由管理员备份知识库数据卷，并验证备份可以恢复。

## 11. 管理员附录

### 修改访问密码

将新密码写入 `deploy/secrets/auth_password`，要求至少 12 个字符、单行、UTF-8 无 BOM。不要把密码
写进 PowerShell 命令历史或提交到 Git。然后只重建 Nginx：

```powershell
Set-Location 'C:\path\to\-RAG-'
docker compose --env-file .env.production up -d --force-recreate nginx
```

修改密码不会改变正在运行的 Cloudflare Tunnel 地址。旧凭据可能被浏览器缓存，验证时使用无痕窗口。

### 运行评估

评估功能当前通过命令行执行，不在网页界面中。进入项目目录并激活虚拟环境后运行：

```powershell
python -m app.evaluation.cli `
  --dataset eval/eval_cases.json `
  --ingest eval/corpus
```

结果保存在：

- `eval/eval_report.md`：适合人工审阅的报告
- `eval/eval_results.json`：适合程序处理的结构化结果

评估现有业务知识库时，应先制作与业务资料匹配的问题、期望来源和答案关键词，不能直接用示例评估集
代表真实业务质量。
